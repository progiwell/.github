# Contributing to Progiwell

Thank you for considering contributing to a **Progiwell** open-source project!

## Workflow

1. **Start with an Issue:** Check existing issues or open a new issue before starting non-trivial changes so requirements and scope are aligned upfront.
2. **Keep Pull Requests Focused:** Keep PRs scoped to a single concern and reviewable in size (ideally `<= 400–600` net changed source lines, with no compiled or generated `dist/` build artifacts committed).
3. **Link the Issue:** Include `Closes #<number>` or `Fixes #<number>` in your pull request description.
4. **Verify Locally:** Run the repository's build, linter, typecheck, and unit tests before opening or updating your PR.

## Standards & Licensing

- Participation in Progiwell repositories is governed by our [Code of Conduct](CODE_OF_CONDUCT.md).
- By submitting a contribution, you agree that your work will be licensed under the target repository's open-source license (`LICENSE`).
